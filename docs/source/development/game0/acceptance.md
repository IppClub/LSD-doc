# 验收方案

本页定义验收要求，不是通过清单。当前源码和已有记录的核对见[当前验收核对](acceptance-current.md)，过程记录见[开发进度](progress.md)。三章已有分段运行证据，最新版本连续试玩、最终美术与发行验收仍未完成。

## 1. 用例矩阵

| ID | 场景与操作 | 通过条件 | 必要证据 |
| --- | --- | --- | --- |
| A01 | 当前引擎加载工程、首次启动、正常退出 | 无加载异常；入口正确；用户现有存档未改写 | 引擎/代码版本、编译操作、完整日志、入口截图 |
| A02 | 加载切片所需角色/场景/音乐/字体及实际动作 | 无缺页、缺贴图、缺动作、乱码；音量与循环正确 | 逐资源核对表、实际截图/音频观察 |
| A03 | 新建、建角、教程操作、击败敌人、搭乘电梯、学院互动 | 事件条件可达；漏操作有提示；场景切换不残留旧输入/HUD/实体 | 连续试玩记录、关键截图、事件日志 |
| A04 | 有效动作、非法按键、idle、取消、重置示范 | 只记录定义允许的样本；标签对应成功动作；数据量受限 | 带版本样本、动作计数与对照日志 |
| A05 | 正常/空/单标签/坏列数据建树；退出时建模完成 | 正常树可执行；失败信息可理解；旧回调不写入新会话；没有非法动作注入 | 最小测试与真实 Unit 执行结果 |
| A06 | 固定种子比较基础 AI、候选模型与上一模型 | 报告采样/合法性/存活等指标；验证场景与示范有区别；学习与 fallback 分开 | 固定输入、树摘要、试战日志和画面 |
| A07 | 采用、放弃、回滚、更换技能、重开游戏 | 只有采用改变生效版本；放弃/失败保持旧版；不兼容有提示 | modelId/version 前后对照、恢复日志 |
| A08 | 基地→训练→编队→实战→结果→基地 | 普通玩家能到达每个入口；没有只能靠 Test 脚本启动的环节 | 完整路径、任务/队伍/模型绑定记录 |
| A09 | 胜利、失败、中止、重试、目标死亡/离场、重复结果事件 | 结果互斥，奖励一次；学员参战；指令失效安全；训练对结果有可解释贡献 | 固定种子用例、状态与奖励变更、战斗截图 |
| A10 | 模型采用后、任务开始前、结果后退出继续 | 状态一致；不重放已完成奖励；角色不被默认值覆盖 | 新/旧存档快照、继续路径日志 |
| A11 | 坏档、上一版本、未知高版本、旧 Config 数据 | 可恢复或明确提示；不静默擦除；迁移有备份 | 模拟数据及迁移/回退结果 |
| A12 | 第一章及最终三章全流程 | 主线节点无死路；通讯和任务事实一致；最终任务后实际呈现结局与署名 | 节点覆盖表、通关版本、结局截图 |
| A13 | 1920×1080、1366×768 与移动横屏候选尺寸 | 文本可读、按钮无遮挡、安全区正确、训练反馈可理解 | 按设备/尺寸保存截图，不以源码代替画面 |
| A14 | 键鼠/所选触摸与手柄范围；失焦、暂停恢复 | 输入不粘连，UI 与战斗控制不冲突，后台不误采样 | 平台版本、实际设备/输入记录 |
| A15 | 核心循环重复 20 次，训练与建模中退出，连续运行 30 分钟 | 无崩溃；事件/实体/资源无持续增长；音频无叠播 | 计数/性能曲线、采集方法、日志；有增长先解释原因 |
| A16 | 干净环境运行最终分发包 | 必需资源齐全；可新建/继续/通关；版本、署名与限制准确 | 包哈希、平台矩阵、打包后完整验收 |

次数和时长是验收起点，不等于每个平台每个任务重复执行同一长稳。存在新风险或改动时扩验证，否则按最小有效用例推进。

## 2. 证据格式

每条结果包含日期、任务 ID、用例 ID、源码提交/工作区状态、引擎版本、操作、预期、实际、日志/截图/数据路径、结论与缺口。结论只用“通过/失败/部分通过/未执行”，部分通过不计入里程碑退出条件。

用独立测试档与固定种子，禁止因无法复现而清空用户数据。测试入口应生成自己的样本和状态，不依赖某个开发者以前留下的数据库。

## 3. 分层验证

编译证明语法/类型/生成产物可用；数据测试证明状态和规则；运行证明引擎真实调用；视觉与操作证明玩家能使用；平台/包验证证明目标设备和分发可用。每项只声明已有的证据层。

12 个现有 Test Yue 入口主要用于 UI/资源原型，不代表 12 个自动化断言。后续自动测试集中在采样正确性、模型合法性、状态迁移、奖励幂等和存档恢复；无需为静态布局写镜像测试。

## 4. 文档验收

本目录必须出现在 Sphinx 导航中；内部页面与来源链接可解析；完整站点构建成功；新文档没有新增解析/缺链接警告；HTML 中能找到新增章节、表格与任务 ID。构建日志需区分既有警告和新增问题。

网站本地构建与公开网站发布是独立结果。公开站点是否更新须在实际发布后核验，本轮不宣称线上文档已更新。

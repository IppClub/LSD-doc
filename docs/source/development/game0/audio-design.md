# Game 0 音频接入与听验

更新：2026-10-04。以下包含最初盘点与接入设计。学院、训练、野外与四类战斗入口已首次接入；真实训练和巡逻入口验证通过，完整覆盖与听验尚未完成，见开发进度。

剧情内容计划要求每个任务具备背景音乐与关键音效。运行工程有13首配乐、2个WAV音效；优先复用并保留原署名。

## 已确认的缺口

接入前显式音乐调用仅在 Tutorial.Level（军事学园）、System.PlayOP（Depart与DepartII）、Story.ValleyVisit（探索）。峡谷另有鸟鸣流水，控制舱有舱门音效。训练、一般探索和大部分战斗没有独立选曲逻辑；是否残留上一场音乐仍需实际听验。不能把音频文件存在或解码成功当作场景已配乐。

## 播放与生命周期约束

1. 统一音乐服务持有当前曲目与所有权标记；同曲换场延续进度，旧场景退出不能停止新场景音乐。
2. 分开音乐、环境声与一次性效果的音量，不通过Audio.globalVolume单独调低音乐。
3. 本机引擎Audio.playStream第三个参数是渐变时间，不是音量。AudioSource支持单源音量与stop(fadeTime)，需在运行时验证后选用。
4. 已检查本机AudioSource.cleanup实现：它清空引用和句柄，没有调用stop。必须在Cleanup回调或主动释放前显式stop，不能假定移除Node会停止循环音频。
5. 切曲、标题退出、重试和存档恢复应有明确释放路径；异步加载必须有请求代次保护，过期请求不能接管播放。
6. 音乐缺失或播放失败应记录文件名并允许游戏继续；不能让音乐加载阻断剧情。

## 验收顺序

先用独立场景验证单源音量、循环、渐变、同曲延续、快速切曲和Cleanup停止，再接入各任务。实际听验覆盖开场、学院跨门、训练进出、探索转战斗、胜败重试、峡谷环境声、重创与终章、结局回标题及继续。每段检查爆音、断音、重复起播、叠音、循环接缝和效果被音乐盖住的问题。运行结果与人耳听验分开记录，最终暂存包须含新服务与完整依赖。

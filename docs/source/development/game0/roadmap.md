## 3. 风险与处理

| 风险 | 尽早验证 | 处理原则 |
| --- | --- | --- |
| 旧资产或脚本与当前引擎不兼容 | M0 | 最小修复并同步生成文件，不先重写全部工程 |
| 学习出来的行为不可理解/不优于基础 AI | M1 | 限定动作和特征，分离 fallback，检查数据采集时点和反馈 |
| 旧战斗方案相互冲突 | P04 | 一个切片只验证一个方向，记录取舍 |
| 三章剧本与角色数量过大 | P13 | 保留主线和角色动机，先完整提纲，支线分期 |
| 主流程依赖原型 UI 中的固定文本 | M2 | 数据服务驱动，UI 原型不算业务完成 |
| 训练模型/剧情存档不兼容 | P11 | 版本化、备份、迁移，独立测试存档 |
| 移动端输入影响示范质量 | M5 前试测 | 先做触摸核心子集，不能把桌面成功代替真机成功 |

## 4. 长程执行节奏

每轮只推进一个可验收的任务或紧密依赖组。开始先读 progress、decisions 与当前代码；结束记录变更、编译/运行/截图证据、失败与下一任务。阶段成果保留可运行包或明确版本，不把未验收功能合并称为完成。

额度不足时保存工作区与进度；后续恢复先读文档，不重复从头盘点。没有用户明确指令，不自动兑换重置卡，不发布网站，也不推送远程。

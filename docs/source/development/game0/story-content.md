## 4. 剧情到运行事件的约定

对话从旧稿整理为 Yarn 及独立任务配置。沿用既有 YarnRunner 和 Command 的可行部分，新增命令只通过统一剧情服务修改状态。

故事节点建议包含 `storyId/nodeId/chapterId/preconditions/sceneId/characters/startEvents/endEvents/rewards`。选择项记录稳定 ID，避免依赖显示文案。重复进入已完成节点不重复解锁或奖励；中途退出后返回对话起点或安全段落，不从动作协程中间恢复。

以任务状态而非玩家在房间停留秒数触发主线。通讯消息可重读，有未读与已读状态；角色对白、任务日志、通讯页面共享同一个剧情事实，避免 UI 固定示例内容与真实进度冲突。

叙事中的“不能读档”保留为世界设定；技术上存档记录玩家离线后的阶段进展，任务重试在剧情说明中解释为演练/再次行动等合适语境，不能用一句设定取消必要的恢复能力。
